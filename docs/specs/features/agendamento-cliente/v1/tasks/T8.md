## 2. Objetivo da Task
Completar o POST público com regras de concorrência permitida, duplicidade diária e preservação da confirmação manual pelo admin.

---

## 3. Descrição Detalhada
- Adicionar cobertura do handler para dois clientes no mesmo slot aguardando confirmação.
- Mapear duplicidade diária do mesmo telefone para erro público seguro sem escrita parcial.
- Garantir que o contrato preserva dados suficientes para o admin confirmar manualmente apenas uma solicitação.
- Nunca retornar dados de terceiros nem informação de concorrência.

### 3.1 Exemplo de Payload
N/A — sem payload parcial.

---

## 4. Aceite Técnico
- [ ] Mesmo telefone/dia ativo retorna erro de duplicidade sem criar novo documento.
- [ ] Pendentes de terceiros no mesmo slot são permitidas sem exposição de terceiros.
- [ ] Duas solicitações no mesmo slot retornam ids distintos e status pendente.
- [ ] Mensagens públicas permanecem genéricas.

### 6.6 Detalhamento dos Casos de Teste
#### CT-011 — Duas solicitações para o mesmo slot podem aguardar
- **Tipo**: service-integration | **Categoria**: regra_negocio
- **Arquivo**: `app/api/public/agendamentos/route.rules.test.ts` (criar)
- **Invariant**: pendentes concorrentes são permitidos sem vazar terceiros.
- **Passos**: enviar dois POSTs para mesmo slot com telefones diferentes.
- **Resultado esperado**: ambos retornam `AGUARDANDO_CONFIRMACAO`; resposta não contém dados do outro cliente.
- **Critérios validados**: CA-07, CA-12, CA-15.

#### CT-012 — Contrato preserva confirmação única administrativa
- **Tipo**: service-integration | **Categoria**: contrato_publico
- **Arquivo**: `app/api/public/agendamentos/route.rules.test.ts` (criar)
- **Invariant**: solicitações do mesmo slot carregam dados suficientes para futura triagem administrativa.
- **Passos**: criar duas solicitações no mesmo slot.
- **Resultado esperado**: retornos têm ids distintos, mesmo profissional/data/horário e status pendente.
- **Critérios validados**: CA-08.

#### CT-013 — Mesmo telefone/dia ativo é bloqueado
- **Tipo**: service-integration | **Categoria**: regra_negocio
- **Arquivo**: `app/api/public/agendamentos/route.rules.test.ts` (criar)
- **Invariant**: duplicidade diária por telefone não cria nova solicitação.
- **Passos**: criar solicitação; repetir no mesmo dia com outro horário.
- **Resultado esperado**: segunda resposta é erro de duplicidade e nenhuma escrita nova ocorre.
- **Critérios validados**: CA-09.
