## 2. Objetivo da Task
Criar Route Handlers públicos de leitura que exponham somente profissionais ativos, dias liberados, horários elegíveis e textos públicos de sucesso.

---

## 3. Descrição Detalhada
- Criar handlers `GET` sob `/api/public/*` conforme Tech Spec.
- Usar `RouteContext`/params assíncronos conforme Next 16.
- Delegar leitura para `agendamentoStore`; handlers não acessam Firestore diretamente.
- Retornar payloads mínimos e esconder detalhes administrativos.
- Horários pendentes de terceiros continuam elegíveis; confirmados não aparecem.
- Configuração de sucesso vazia retorna corpo vazio/seguro para fallback do cliente.

### 3.1 Exemplo de Payload
N/A — endpoints GET sem payload.

---

## 4. Aceite Técnico
- [ ] Cada rota GET retorna JSON tipado e status HTTP adequado.
- [ ] Profissionais inativos não aparecem.
- [ ] Dias e horários respeitam elegibilidade pública.
- [ ] Configuração ausente não quebra a jornada.
- [ ] Nenhum endpoint retorna dados de terceiros.

### 6.6 Detalhamento dos Casos de Teste

#### CT-030 — GET profissionais retorna somente campos públicos
- **Tipo**: route-integration | **Categoria**: contrato_api_publica
- **Arquivo**: `app/api/public/profissionais/route.test.ts` (criar)
- **Invariant**: endpoint público de profissionais expõe apenas ativos e DTO mínimo.
- **Owning layer**: `route-integration` | **Real execution boundary**: `http`
- **Pré-condições**: store fake com um profissional ativo e um inativo.
- **Passos**: executar handler GET.
- **Resultado esperado**: JSON contém apenas o profissional ativo com `id`, `nome`, `cref`.
- **Negative companion**: incluir inativo na fixture e afirmar ausência.
- **Critérios validados**: CA-04, CA-15.

#### CT-031 — GET dias retorna dias liberados sem detalhes internos
- **Tipo**: route-integration | **Categoria**: contrato_api_publica
- **Arquivo**: `app/api/public/profissionais/[profissionalId]/dias/route.test.ts` (criar)
- **Invariant**: endpoint de dias retorna somente datas liberadas do profissional.
- **Resultado esperado**: apenas `data` e `label` de dias ativos; sem horários ou flags internas.
- **Critérios validados**: CA-05, CA-15.

#### CT-032 — GET horários exige data válida
- **Tipo**: route-integration | **Categoria**: validacao_negativa
- **Arquivo**: `app/api/public/profissionais/[profissionalId]/horarios/route.test.ts` (criar)
- **Invariant**: data ausente/malformada falha sem consultar store.
- **Resultado esperado**: 400 público de data inválida; store não chamada.
- **Critérios validados**: CA-06, CA-15.

#### CT-033 — GET horários retorna pendentes elegíveis e exclui confirmados
- **Tipo**: route-integration | **Categoria**: contrato_api_publica
- **Arquivo**: `app/api/public/profissionais/[profissionalId]/horarios/route.test.ts` (criar)
- **Invariant**: confirmados não aparecem e pendentes de terceiros não são sinalizados.
- **Resultado esperado**: horários livre/pendente retornam como DTO simples; confirmado ausente.
- **Critérios validados**: CA-06, CA-07, CA-15.

#### CT-034 — GET configuração de sucesso trata textos como texto simples
- **Tipo**: route-integration | **Categoria**: configuracao_publica
- **Arquivo**: `app/api/public/configuracao/sucesso/route.test.ts` (criar)
- **Invariant**: configuração pública é texto simples e ausência usa fallback seguro.
- **Resultado esperado**: strings retornam sem HTML renderizável; ausência/erro retorna vazio seguro.
- **Critérios validados**: CA-13, CA-14, CA-17.
