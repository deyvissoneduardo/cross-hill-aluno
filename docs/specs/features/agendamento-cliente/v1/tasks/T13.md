## 2. Objetivo da Task
Implementar revisão, submissão da Solicitação de Agendamento, erro recuperável e tela de sucesso com configuração pública/fallback.

---

## 3. Descrição Detalhada
- Criar `ReviewStep` com `SummaryList` e aviso de aguardando confirmação.
- Criar `SuccessStep` com textos configurados ou fallback seguro.
- Integrar submit via `agendamentosRepository`.
- Tratar duplicidade diária, antiabuso e 5xx com mensagens genéricas conforme spec.
- Não exibir identificadores internos na URL nem detalhes de terceiros.

### 3.1 Exemplo de Payload
N/A — payload é montado internamente a partir do estado e DTO de T9.

---

## 4. Aceite Técnico
- [ ] Revisão mostra nome, telefone, profissional, data e horário antes do envio.
- [ ] Submit bem-sucedido mostra sucesso aguardando confirmação.
- [ ] Configuração pública é usada quando existir.
- [ ] Fallback seguro é usado quando configuração estiver ausente.
- [ ] Falha de envio mantém fluxo recuperável.
- [ ] Duplicidade diária mostra mensagem definida.
