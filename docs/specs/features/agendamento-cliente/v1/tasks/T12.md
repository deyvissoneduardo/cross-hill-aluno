## 2. Objetivo da Task
Implementar a etapa de seleção progressiva de profissional, dia e horário com loading, vazio, erro e privacidade.

---

## 3. Descrição Detalhada
- Criar `ScheduleStep` consumindo repositories de profissionais e disponibilidade.
- Carregar profissionais após identificação válida.
- Resetar dependências quando seleção pai mudar.
- Renderizar dias e horários apenas após seleção anterior.
- Exibir estados vazios e erros contextuais sem revelar dados administrativos ou concorrência.

### 3.1 Exemplo de Payload
N/A — componente consome repositories.

## 4. Aceite Técnico
- [ ] Profissionais ativos aparecem como cards selecionáveis.
- [ ] Dias liberados aparecem após profissional selecionado.
- [ ] Horários elegíveis aparecem após dia selecionado.
- [ ] Estados vazios bloqueiam progressão e mostram mensagens do design.
- [ ] Não há contador/dados de terceiros em nenhum estado.
