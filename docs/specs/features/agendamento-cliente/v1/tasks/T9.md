## 2. Objetivo da Task
Criar repositories de browser com `fetch` nativo para consumir o BFF público, mapear DTOs para modelos e normalizar erros para a UI.

---

## 3. Descrição Detalhada
- Criar repositories em `app/agendamento/repositories/*.ts`.
- Nenhum componente chama `fetch` diretamente.
- Mapear status HTTP para erros de domínio: validação, duplicidade, antiabuso, servidor e rede.
- Ignorar campos extras inesperados nos DTOs.
- Usar endpoints públicos definidos nas tasks T5/T7/T8.

### 3.1 Exemplo de Payload
N/A — repositories apenas consomem contratos existentes.

---

## 4. Aceite Técnico
- [ ] Cada repository exporta funções tipadas e não expõe `Response` cru.
- [ ] Erros são convertidos para sentinelas consumíveis pela UI.
- [ ] DTOs públicos são mapeados sem dados de terceiros.
- [ ] MSW cobre sucesso e falhas principais.
