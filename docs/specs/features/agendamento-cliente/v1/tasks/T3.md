## 2. Objetivo da Task
Implementar validações puras de nome/telefone e a inicialização Firebase Admin restrita ao servidor.

---

## 3. Descrição Detalhada
- Criar `app/agendamento/validation/cliente.ts` com normalização de nome e telefone brasileiro.
- Criar `lib/firebase/admin.ts` lendo apenas `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL` e `FIREBASE_PRIVATE_KEY`.
- Garantir que nenhuma variável Firebase usa prefixo `NEXT_PUBLIC_` e que erros não serializam segredo.
- Não criar `.env` nem credenciais reais.

### 3.1 Exemplo de Payload
N/A — sem payload parcial.

---

## 4. Aceite Técnico
- [ ] Validação normaliza telefone brasileiro para formato `55...` e rejeita entradas inválidas.
- [ ] Validação normaliza nome e rejeita vazio, curto, abusivo ou acima do limite.
- [ ] Firebase admin é inicializado somente server-side por variáveis `FIREBASE_*`.
- [ ] Nenhum código client-side importa `lib/firebase/admin.ts`.

### 6.6 Detalhamento dos Casos de Teste
#### CT-004 — Normalização e validação rejeitam telefone inválido
- **Tipo**: unit | **Categoria**: validação
- **Arquivo**: `app/agendamento/validation/__tests__/cliente.test.ts` (criar)
- **Invariant**: telefone válido deve ser persistido normalizado e telefone inválido não deve avançar.
- **Owning layer**: `unit` | **Real execution boundary**: `none`
- **Passos**: chamar normalização/validação para cada entrada.
- **Resultado esperado**: entradas válidas retornam `5561999999999`; inválidas retornam erro específico de telefone.
- **Critérios validados**: CA-02, CA-03.

#### CT-028 — Firebase admin permanece server-only
- **Tipo**: unit | **Categoria**: seguranca_server_only
- **Arquivo**: `lib/firebase/admin.test.ts` (criar)
- **Invariant**: credenciais Firebase server-side nunca podem ser lidas por módulos client-side.
- **Owning layer**: `unit` | **Real execution boundary**: `filesystem`
- **Passos**: testar env incompleto e tentativa controlada de import client-side.
- **Resultado esperado**: configuração incompleta é rejeitada; variável `NEXT_PUBLIC_FIREBASE_*` não é usada; erro não serializa segredo.
- **Critérios validados**: CA-15.

#### CT-029 — Validação de nome normaliza e rejeita inválidos
- **Tipo**: unit | **Categoria**: validacao_negativa
- **Arquivo**: `app/agendamento/validation/__tests__/cliente.test.ts` (criar)
- **Invariant**: nome do cliente só é aceito quando, após normalização, representa nome humano mínimo e seguro.
- **Owning layer**: `unit` | **Real execution boundary**: `none`
- **Passos**: executar tabela com nomes válidos, vazios, curtos, HTML/script e acima do limite.
- **Resultado esperado**: válidos retornam valor normalizado; inválidos retornam erro específico de nome.
- **Critérios validados**: CA-02, CA-03.
